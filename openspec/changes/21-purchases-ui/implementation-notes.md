## Decisions (conservative defaults, owner can overrule)
1. **Purchases are owner-only end to end.** The database already lets only an owner post/cancel; supplier rates and input tax are not counter data. Actions use `requireAdminMember` (drafts too), the proxy redirects a counter session off `/purchases/**`, and the nav hides it. Tests in `access.test.ts`, `nav.test.ts`, `purchases.test.ts`. **Not closed:** RLS still lets a counter session insert/edit *draft* purchase rows through the API (policy `insert_draft ... is_active_member()`); they cannot post. Same accepted class as attack-test K1–K4; tightening it to admin belongs with a DB change reviewed by Opus.
2. **Supplier's bill number and date are required** on the screen (the DB columns are nullable: opening rows and older data stay valid). The supplier's bill may not be dated after the day it was received.
3. **Duplicate check in two places**: early, friendly (`billNumberTaken`, posted bills of the same supplier, case-insensitive) on save and post; the unique index is the guard for races. Drafts may repeat a number until one is posted.
4. **Item picker offers stock items only** (`post_purchase_invoice` refuses `non_stock_line`); the server checks it too.
5. **`rcm` is never sent from the form** (`rcm: false` on every save; the DB refuses `rcm = true` with `rcm_purchase_unsupported`). RCM freight is 21b.
6. **`taxable_value: 0` on draft lines** — the purchase-lines column is NOT NULL with no default (sales lines got a default in change 03); the posting function overwrites it. No migration for that.
7. Cancelling a bill whose goods were sold gets its own sentence pointing at a debit note (the generic negative-stock text says "reduce the quantity", which is wrong here).
8. List tiles: payable = Σ `v_open_purchase_invoices.open_amount` via `completeRows` (a list cut short by `max_rows` throws instead of showing a wrong total); ITC and RCM payable from the owner-only `v_trial_balance` ledgers. "Rebate accrued" tile waits for change 24.
