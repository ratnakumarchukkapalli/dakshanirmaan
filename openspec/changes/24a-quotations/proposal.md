# 24a — quotations (first third of change 24; 24b rebates, 24c interest follow)

Skill: daksh-schema + daksh-posting (DB half: tables, RLS, numbering, conversion function, pgTAP) · daksh-api + daksh-ui (actions, screens). Model: Opus for the DB half, Sonnet for the screens.
Spec section: openspec/specs/db-architecture/spec.md → "quotations + quotation_lines (Phase 2)" (line ~176) and the `delivery_challans` section for the convert-to-invoice precedent; api-architecture → `quotes.ts` (`saveQuote`, `markQuote`, `convertQuoteToInvoice`); frontend-architecture sales routes.
Context: customers ask for rates before buying ("estimate for 200 bags + 2 tonne TMT"). Today the family writes it on paper. A quotation is a priced list of items for a customer, valid until a date, that can later become a sales invoice at exactly the quoted rates. It **never posts**: no journal entry, no stock movement, no GST liability, and it is not a tax document.
Do not: post anything to `journal_*` / `stock_movements`; reserve or reduce stock; consume the GST invoice number series (a quote has its own `QT` series); change `post_sales_invoice`; show cost or margin anywhere on the quote.

## Scope

### DB half (Opus)
1. **Tables** `quotations`, `quotation_lines` per the spec: header `quote_no UNIQUE, quote_date, party_id (customer or both), valid_until (>= quote_date), status ('open'|'accepted'|'expired'|'converted'), converted_invoice_id NULL, note (<= 500), warehouse_id (default sales warehouse; needed by the invoice), updated_at, created_by`; lines snapshot `item_id` + name, HSN, GST rate, UOM, `qty NUMERIC(12,3) > 0`, `rate NUMERIC(14,4) >= 0`, line discount if sales lines have one (mirror `sales_invoice_lines` pre-tax columns, no tax amounts stored). `set_created_by`, RLS: any active member reads/writes while `status = 'open'` (or `accepted` for status moves), nobody writes `converted` rows except the conversion function; no DELETE grant (a quote that is no longer wanted is set to `expired`). `ALTER TYPE source_type ... 'quotation'` already exists.
2. **Numbering:** `QT/yy-yy/nnnn` from `next_doc_no('QT', date)`, **assigned when the quote is first saved** (quotes have no draft state), gapless is not required but never reused. Add the series wherever fiscal years/series are seeded (look at `ensure_fiscal_year` / `doc_sequences`) so a new FY gets it.
3. **Totals for display** are computed in the database (never TypeScript): a read view or function `quotation_totals(quote_id)` / `v_quotations` returning taxable, CGST/SGST/IGST (place of supply derived exactly the way `post_sales_invoice` derives it: party state vs organisation state, using the party's billing state; if the compute is embedded in `post_sales_invoice` and not reusable, extract it into a shared immutable helper used by both WITHOUT changing posted results — all existing pgTAP must stay green) and grand total. Rounded to rupees with the same round-off rule as invoices.
4. **`save_quotation`-style write path:** either plain RLS inserts or one function; your call, but item name/HSN/GST must be snapshotted server-side from `items` at save time (never trusted from the client), a draft/stale write carries `updated_at` and is refused with `DN_CONFLICT`-style code the app maps to `conflict`, and an inactive item is refused (`DN_VALIDATION:item_inactive`).
5. **`convert_quotation_to_invoice(p_quote_id) → uuid`** (SECURITY DEFINER, active member): locks the quote; allowed from `open` or `accepted`; refuses `expired`/`converted` (but a repeat call on a `converted` quote returns the same `converted_invoice_id`, idempotent), refuses when `valid_until < today (org timezone)` with `DN_VALIDATION:quote_expired`, refuses an inactive item/party naming the problem; creates a **draft** sales invoice (same columns the app's draft-invoice save writes: party, addresses from the party's defaults, warehouse, place of supply derived, lines at the quoted qty/rate/discount; GST re-read at post as for any draft), sets the quote `converted` + `converted_invoice_id` in the same transaction. Nothing posts; the user reviews and posts the invoice through the normal flow. Concurrency: two simultaneous conversions create exactly one invoice.
6. **`mark_quotation(p_quote_id, p_status)`**: `open → accepted | expired`, `accepted → open | expired`; never to/from `converted` by hand.
7. **v_attention / expiry:** a quote whose `valid_until` has passed while `open`/`accepted` reads as `expired` in a view (`v_quotations.effective_status`), no scheduled job. Optional: open quotes expiring within 2 days appear in `v_attention` only if that is a one-line addition; otherwise skip and note it.
8. **pgTAP** (empty DB): create with snapshots; totals match what `post_sales_invoice` computes for the same lines (intra-state and inter-state); counter user can create and convert; non-member cannot read; converted quote immutable; expired refused; double convert returns the same invoice and creates one; inactive item refused; stale write refused; numbering per FY; no journal / stock rows are ever written; catalog guard (00026) still passes.

### App half (Sonnet) — after the DB half is reviewed
9. `src/app/actions/quotes.ts` (`saveQuote`, `markQuote`, `convertQuoteToInvoice`) with zod in `src/schemas/quotes.ts`, envelope, role gate (any member), revalidate.
10. **Screens** under Sales: `/sales/quotes` (list: tiles open / accepted value / expiring soon, filter by status, search by party), `/sales/quotes/new` + `?id=` edit (reuse the invoice form's line editor and item picker as far as practical, no stock/credit-limit checks, no payment fields), `/sales/quotes/[id]` view (print-friendly page titled **Quotation**, validity line, terms note, totals from the database, buttons: Edit while open, Mark accepted / expired, **Convert to invoice** → lands on the new draft invoice). A PDF / share link only if the invoice PDF component can be reused with a "Quotation" title and without tax-invoice fields (IRN, e-way bill, "Original for recipient"); otherwise the print stylesheet is the deliverable. en + te strings, 390 px, both themes. Sidebar/Sales tabs get a Quotes entry.

## Conservative defaults (log in implementation-notes.md)
1. Any active member (counter included) creates, edits, accepts and converts quotes; converting only produces a draft invoice, so posting rules and credit limits still apply later.
2. Rates are frozen at quote time; the converted invoice uses them even if the item master changed, but GST rate/HSN are re-read at posting, as for every draft.
3. A quote cannot be deleted; unwanted quotes are marked expired.
4. No stock reservation, no price validation against cost, no customer-facing e-signature or portal.
5. Expiry is computed from `valid_until`, no background job.
