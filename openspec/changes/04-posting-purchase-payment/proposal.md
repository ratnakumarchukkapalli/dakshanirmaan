## Scope

1. **`post_purchase_invoice(p_invoice_id uuid) RETURNS uuid`** — Dr Inventory taxable (+ tax when `itc_eligible = false`) · Dr input CGST/SGST or IGST when eligible · Cr AP(party) · round-off; stock IN at cost; weighted average recomputed after item lock. Uses `purchase_invoices.warehouse_id`.
2. **`post_payment(p_payment_id uuid) RETURNS uuid`** — receipt: Dr cash/bank (or `cheques_in_hand` for cheque) · Cr AR(party), `discount > 0` → Dr `discount_allowed`; payment: mirrored, discount → Cr `discount_received`; cheque payment Cr bank at post, status `issued`.
3. **`payment_allocations` trigger** — per-payment Σ ≤ amount; each allocation ≤ invoice open amount; `invoice_type` must match `payments.direction`. Unallocated remainder = on account.
4. **Cheque lifecycle** — add `cheque_status` enum + payments columns per spec; `cheques_in_hand` system_key + account 1130; `deposit_cheque(id)`, `mark_cheque_cleared(id)` (status only), `bounce_cheque(id, p_reason)` (admin; reversal of receipt, or of deposit + receipt if deposited; allocations deleted so invoices re-open; `bounce_reversal_entry_id` set). Invalid transitions raise `DN_CHEQUE_STATE`. **Actor from `auth.uid()`** — the older spec text `bounce_cheque(p_payment_id, p_actor)` is superseded by the audit; log the deviation in implementation-notes.
5. **`post_expense_voucher(p_voucher_id uuid) RETURNS uuid`** — generic expense/advance lines; advance (`user` limit ₹5,000, `DN_FORBIDDEN` above), salary (gross via `salary_payable`, recovery of `employee_advance`, net cash/bank), daily wages for named worker, unnamed hamali (no party). **RCM freight**: `expense_vouchers.purchase_invoice_id` column; RCM line additionally Cr `rcm_payable` 5% and Dr `input_cgst`/`input_sgst` 2.5% each.
6. **`cancel_document` extended** (new `CREATE OR REPLACE`, same signature) with `purchase_invoice`, `payment`, `expense_voucher` branches: `DN_HAS_ALLOCATIONS` for purchase invoices with allocations, `DN_NEGATIVE_STOCK` when the reversal would take stock below zero, mirror-image reversal + stock movements, `DN_NOT_POSTED` idempotency. Cancelling a cheque receipt that is bounced/cleared follows the state machine (decide conservatively, log in notes).
7. **Grants** per change 03: `post_*`, `cancel_document`, cheque transitions → `authenticated` + `service_role`; nothing for `anon`; default privileges already revoke from public — verify on every new function.
8. New `system_key`s needed (`cheques_in_hand`, and any of `bank`, `discount_allowed`, `freight_inward`, `loading_unloading`, `rcm_payable`, `employee_advance`, `salary_payable`, `input_*` not yet seeded) — check what change 01/03 already seeded before adding.
