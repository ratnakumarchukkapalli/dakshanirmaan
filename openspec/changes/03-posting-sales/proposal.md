This change adds the first posting functions: gapless document numbering, the sales-invoice posting path (the highest-traffic document — daily billing runs on it), its reversal, and the stock-valuation query every other posting function will depend on. A pre-implementation audit and a system-design audit (both 2026-09-16, Fable) landed on `main` while this change was mid-implementation and revised the governing spec: the actor is now derived from `auth.uid()` inside every function, never passed as a parameter — the exact class of bug a fresh Opus review of the first draft had separately found and proven exploitable (unauthenticated writes via `anon`, actor impersonation). This proposal and the implementation were rebuilt against the audited spec. See implementation-notes.md for the full arc.

## Scope

From the "Posting engine" requirement plus the audit's clarifications, scoped to change 03:

1. **`stock_on_hand(p_item uuid, p_warehouse uuid) RETURNS TABLE(qty numeric, value numeric, avg_rate numeric)`** — `SECURITY INVOKER` (not DEFINER — a direct call is subject to `stock_movements`' own RLS).
2. **`next_doc_no(p_series text, p_date date) RETURNS text`** — row-locked, gapless per `(series, fy_label)`; auto-creates the next FY's row for a series that already exists (fiscal-year rollover needs no manual seed step); no grant to any role, internal-only.
3. **`post_sales_invoice(p_invoice_id uuid, p_override_credit bool DEFAULT false) RETURNS uuid`** — actor = `auth.uid()` (never a parameter); lock order document → party → every item touched (ascending id, one `FOR UPDATE` per item in a loop, not a single `ORDER BY ... FOR UPDATE` — Postgres doesn't guarantee the latter locks in that order) → `doc_sequences` (inside `next_doc_no`, last); role gate (both roles may post); period lock; `DN_VALIDATION:no_lines`/`invalid_party` guards; per-line recompute of taxable/CGST+SGST-or-IGST (never trusts the line's own stored amounts); non-stock lines (`items.is_stock = false`) route to `freight_recovered`, no stock movement; stock lines route by category to `sales_cement/steel/other`; round-off ±₹0.50 sanity (`DN_UNBALANCED`); credit-limit check against net AR balance, admin-only override; journal + `stock_movements` OUT at weighted-avg (`DN_NEGATIVE_STOCK` if it would go negative); finalize + audit row (records `override` flag).
4. **`cancel_document(p_source_type source_type, p_source_id uuid, p_reason text) RETURNS uuid`** — actor = `auth.uid()`, admin-only; `sales_invoice` branch: `DN_NOT_POSTED` if not posted, `DN_HAS_ALLOCATIONS` if a `payment_allocations` row references it, `DN_PERIOD_LOCKED` if today's (IST) period is locked; mirrors every journal line and stock movement (`reversal_of` marks the mirror so a reversal can never itself be re-reversed), sets `reversed_by` on the original entry, dates the reversal today (IST) so a locked original period never blocks a correction.
5. **Schema additions**: `organization.timezone` (IST default), `items.is_stock`, `parties.is_walk_in` + walk-in party seed, `warehouse_id` on `sales_invoices`/`purchase_invoices`, `stock_movements.reversal_of`, `sales_invoice_lines.taxable_value DEFAULT 0`, `warehouses (is_default) WHERE is_default` unique index, retroactive `system_key` on 7 accounts (`sales_cement/steel/other`, `freight_recovered`, `discount_received`, `salaries`, `godown_rent` — this also updates change 01's frozen `00002_seed_creates_system_keys.test.sql` count from 25 to 32, a deliberate spec-directed change, not an accidental break).
6. **Function exposure**: `ALTER DEFAULT PRIVILEGES ... REVOKE EXECUTE ... FROM public` plus explicit `REVOKE`/`GRANT` on every function created by changes 01–03 (trigger functions get no grant to anyone; `is_active_member`/`current_app_role` keep `authenticated` since RLS policies call them directly; `post_*`/`cancel_document`/`stock_on_hand` get `authenticated` + `service_role`; `next_doc_no` gets none). `audit_log` gets the same insert-only trigger as the ledger.

## Done when

- pgTAP: **"posting a sales invoice keeps books balanced"** and **"cancelled invoice reverses, never deletes"** — DESIGN.md §3 worked example, called by a real `authenticated` session (not `postgres`), Σdebit = Σcredit = ₹1,32,100.
- Also covered: round-off both directions, IGST path, non-stock (freight) lines, credit limit + admin-only override, `DN_HAS_ALLOCATIONS`, `DN_NOT_DRAFT` (cancelled and already-posted re-post), `DN_NEGATIVE_STOCK` (+ atomicity), `DN_VALIDATION:no_lines`/`invalid_party`, `next_doc_no` gapless/per-series/FY-rollover, and that `anon` has zero access to any of these functions.
