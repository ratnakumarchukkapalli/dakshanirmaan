## Scope
**In — database (Opus)**
1. **`post_credit_note(p_note_id)`** (sales return / rate difference): reverses revenue and output GST **proportionally to the note lines** (Dr Sales income per the original line's income account, Dr CGST/SGST/IGST output, Cr Debtors for `grand_total`); for goods returned, stock comes back IN **at the original COGS rate** of the invoiced line and COGS is reversed (Dr stock, Cr COGS). `place_of_supply` is derived from the invoice (or the party rule when there is none), as in `post_sales_invoice` — never trusted from the client. Snapshots tax/HSN/name on lines; money `numeric(14,2)`, rounding and round-off exactly like the invoice.
2. **`post_debit_note(p_note_id)`** (purchase return / rate difference): mirror — Dr Creditors, Cr purchases/stock, Cr input GST (ITC reversed); goods leave stock at the **purchase's rate**; refuses `DN_NEGATIVE_STOCK` when the quantity is not on hand (the documented remedy for a bill that cannot be cancelled).
3. **Guards:** admin at aal2 only; document must be draft; note lines' qty per invoice line ≤ invoiced qty − prior *posted, uncancelled* notes (`DN_VALIDATION:qty_exceeds_invoice`), checked under the invoice's lock; party matches the invoice; invoice is posted (not cancelled); note `grand_total` may not exceed the invoice's remaining open amount unless the invoice is already fully paid (then the excess becomes a credit balance — see default 2); period lock respected; date not in the future; lock order per db spec (Non-functional invariants).
4. **Numbering:** two gap-free per-FY series through `next_doc_no` (`CN/`, `DBN/` unless the spec's numbering clarification says otherwise); GST-reportable.
5. **`cancel_document`** for both note types: reversal dated on the note's own date, stock movement reversed, refused if the reversal would break a later movement (same rule as purchases) and if the note's period is locked.
6. pgTAP (new file per note type) + grants/`explicit_grants` conventions + the L1 catalog guard (`00026`) stays green.

**In — screens (Sonnet, after the DB is reviewed)**
7. `notes.ts`: `saveDraftNote`, `postNote(id)`, `cancelNote`; zod; error-envelope mapping for the new `DN_*` codes; the server never computes tax (reads it back from the post function, like invoices).
8. **Credit note:** "Credit note" button on the posted invoice view → `sales/credit-notes/new` prefilled from the invoice (lines with a remaining-returnable qty, reason, "goods returned to stock?" switch), draft/post/cancel, posted view with its journal entry; "Credit notes" segment on the sales list (already in the spec tree).
9. **Debit note:** same from the posted purchase bill view (or Purchases list until change 21 lands the bill screen — log which).
10. en + te strings, en-IN money, `DD-MM-YYYY`, both themes, 390 px.
**Out:** PDF for notes (reuse the invoice PDF route only if it takes a document type cheaply; otherwise log as a follow-up), refunds of cash to the customer/supplier (a manual admin journal today; `payments.direction = 'refund'` is a later change), the customer interest debit note (24), reconciling notes with the bank (22).

## Conservative defaults (log each in implementation-notes.md; owner can overrule)
1. **Return vs price adjustment.** A note either returns goods (qty > 0, stock effect) or only adjusts value (rate difference, discount after the fact: no stock effect, qty checks skipped, taxable value adjustment only). Schema has no flag for this today — add a header column `stock_effect boolean not null default true` in the migration rather than overloading qty. Rate-difference notes still cannot exceed the invoice line's taxable value.
2. **Note on an already-paid invoice** does not touch the receipt; the customer's account simply goes credit (shows as advance/negative outstanding). The ageing report and party ledger must show it correctly — verify, do not assume.
3. **A note without `against_invoice_id`** is refused in Phase 2 (`DN_VALIDATION:note_needs_invoice`) except for an admin-posted value-only note; returns always need the invoice.
4. **Counter staff** cannot create note drafts either (RLS insert policy allows drafts today: tighten to admin in this migration, matching the API spec) — confirm before tightening, and log it.
5. Reason is required text on post.
