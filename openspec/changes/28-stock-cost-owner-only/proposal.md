# 28 — stock-cost-owner-only (owner decision 1, 2026-09-21; confirmed by Ratna 2026-09-26 after the Phase 1 review)

Skill: daksh-schema (column grants, views, RLS, pgTAP) + daksh-posting (read-only: `stock_on_hand`, weighted-average cost must not change) + daksh-ui (screens that show cost). Model: Opus for the database part, Sonnet for the screens. Have the result reviewed by a separate Opus before commit (it rewrites views that reports and the dashboard read).
Spec section: openspec/specs/db-architecture/spec.md → "RLS and roles" (role matrix, "P&L/BS views admin-only") and the "Not closed (c)" bullet under "Implementation clarifications: owner-only salary data" — that bullet is what this change closes. Pattern to copy: how change 13 hid `parties.monthly_salary` / `daily_wage` (column-level SELECT not granted, owner-only RPC + admin-gated views).
Context: the counter (`user`) must not see what stock costs the family. The screens already omit cost, but the database still returns it: `v_stock_summary` / `v_stock_summary_all` (`avg_rate`, `value`), `v_stock_ledger` / `v_stock_ledger_all` (`rate`, `value`), `stock_movements.rate` / `.value`, and the function `stock_on_hand()` (`qty, value, avg_rate`). A counter with the public key can read them through the REST API (Phase 1 review 2026-09-26, finding M4). Quantities stay visible to both roles: the counter needs on-hand qty to bill.
Do not: change posting maths or weighted-average cost; hide quantities; break `post_*` functions (they are SECURITY DEFINER and read cost themselves); touch journal tables directly; give the counter a way to derive cost from another visible object (check `journal_lines` on the Inventory / COGS accounts — those are readable today; decide with Ratna whether COGS on invoices is in scope or an accepted residual, and write it into the spec either way).

## Scope
1. Discovery first (short, written into implementation-notes.md): list every table, view, function and screen that exposes stock cost (`avg_rate`, `rate`, `value`, `cogs`, inventory value tiles on the dashboard and reports, the Excel export, `v_attention` if it prints values). Include the direct `journal_lines` route and say what stays open.
2. Database: split the read model so a `user` gets quantity-only objects and an admin (at aal2) gets cost. Preferred shape: column-level `REVOKE SELECT (rate, value)` on `stock_movements`, quantity-only variants of the two summary views and two ledger views (or the same views with cost columns produced by an admin-gated expression returning NULL for a counter — pick one and keep `security_invoker`), `stock_on_hand()` cost columns NULL for a non-admin. Admin path unchanged in values.
3. Screens: stock, item and report screens read the quantity-only shape for a counter and show no cost column, tile or Excel column; owner screens unchanged. No hardcoded role checks in TS that the database does not also enforce.
4. pgTAP (new file, empty database, `supabase test db`): as `user` at aal1 and aal2, `select rate/value/avg_rate` from each object is denied or NULL, quantities are identical to the admin's; admin at aal2 sees the same figures as before; admin at aal1 sees nothing; posting a sale as `user` still works and its COGS is still booked correctly; the existing suite (1779+ tests) still passes.
5. Docs: update the spec "Not closed (c)" and STATUS; log any residual (COGS in `journal_lines`) in implementation-notes.md.

## Done when
pgTAP green on an empty database, vitest/tsc/lint/build clean, and a real-browser walk as a counter user (stock, item, reports, dashboard show no cost) and as an owner (all cost figures unchanged and equal to the trial balance's Inventory account).
