## Scope decisions (conservative defaults, logged here per project.md §Build process)

- **Enums**: only the base set from "Enums and reference types". The `ALTER TYPE source_type ADD VALUE ...` and `CREATE TYPE cheque_status` in "Schema extensions" are deferred to the migrations that introduce the tables using them (challans/transfers/day_close in change 05; cheque lifecycle in change 04) — `ALTER TYPE ... ADD VALUE` must be committed before use, so bundling it here with no consumer yet is pure risk for no benefit.
- **Seed CoA**: includes accounts for *all* `system_key`s named anywhere in the spec (the 15 in "Core tables" + the 10 added in "Schema extensions" — `bank, cash_over_short, rebate_income, rebate_receivable, stock_loss, freight_inward, loading_unloading, discount_allowed, interest_income, goods_in_transit`), since the README row for this change says "seed CoA (incl. new system keys)" explicitly and these are just `accounts` rows, not new tables — no dependency on the tables those later features add.
- **app_users**: only the base RLS-section shape (`user_id, role, name, is_active`). The `locale, invited_by, invited_at` columns and the max-10-active-users trigger are "Schema extensions" tied to change 08 (`auth-users`, which builds invite/disable) — adding them here with nothing to set them is premature.
- **RLS policy granularity**: SELECT for active members on every table (spec: "Active members: SELECT on business tables"). INSERT/UPDATE for both roles on draft-status document tables (headers gated on `status = 'draft'`; lines follow their header). Everything else — master/reference tables (`organization, accounts, parties, party_addresses, items, warehouses, fiscal_periods, doc_sequences`), `app_users` writes, and the ledger core (`journal_entries, journal_lines, stock_movements`) — gets **no INSERT/UPDATE/DELETE policy at all** (admin-only writes for masters go through `service_role`/future admin actions in change 09; ledger-core writes stay `SECURITY DEFINER`-only per spec, arriving in change 02+). This is the most conservative reading of "deny-by-default" and avoids guessing at masters-data UX that change 09 (`masters`) actually owns.
- **audit_log**: SELECT for active members, no INSERT policy for `authenticated` — rows are written by `post_*`/`cancel_*` functions (change 02+), which are `SECURITY DEFINER` and bypass RLS. Nothing writes it yet in this change, so this is inert but correctly shaped.
