# 22 — bank-recon (HDFC statement import and reconciliation)

Skill: daksh-schema + daksh-posting (DB half: tables, import/match functions, view, RLS, pgTAP) · daksh-api + daksh-ui (app half: parser, actions, screens). Model: Opus for the DB half, Sonnet for the parser and the screens.
Spec section: openspec/specs/db-architecture/spec.md → "bank_statements + bank_statement_lines" (line 187). Research (read it, it is the format contract): `docs/research/hdfc-statement-format.md`.
Context (owner, 2026-09-26): one HDFC current account, mostly UPI / NEFT / IMPS, few cheques, some cash deposits. The owner wants to download the statement from NetBanking, import it, see what matches the books, and book what is missing (bank charges, receipts nobody recorded). Both tables already exist from change 01 (owner-only RLS, `match_status`, `matched_payment_id`, `matched_entry_id`); this change adds what they lack and builds everything on top.
Do not: write `journal_lines` / `stock_movements` from the app (new entries are created only through the existing `post_*` actions); auto-post anything from a statement line; store the uploaded file or the account number from the preamble; let a counter user read or write any of it; use the `xlsx` package; use floats for money.

## Scope

### DB half (Opus)
1. **Columns the spec lacks** on `bank_statement_lines`: `value_date date`, `reference text` (normalised: zero-padding stripped, upper-case, null when all zeros), `line_no int` (file order), `dedupe_key text NOT NULL`, `matched_at`, `matched_by`. Unique `(statement_id... )` is NOT enough for re-imports: add a unique index on `dedupe_key` per bank account (join via statement) — implement as a column `account_id` copied onto the line, or a unique index through a trigger-free design of your choice, but a line already imported must never be imported twice. Key = `(txn_date, debit, credit, balance, reference, occurrence_in_file)` per the research (section 5). Lines are immutable except the match fields (trigger, like the posted-row guards).
2. **`import_bank_statement(p_account_id, p_source_file, p_lines jsonb) → jsonb`** (SECURITY DEFINER, admin at aal2 only, `DN_FORBIDDEN` otherwise): validates every line (`^\d+(\.\d{1,2})?$` strings, exactly one of debit/credit > 0, date not in the future), checks the **balance chain** inside the file (`prev balance + credit − debit = balance`; a break raises `DN_VALIDATION:balance_chain_broken` naming the line), computes dedupe keys, inserts the statement and only the not-yet-imported lines (skips duplicates and reports `{imported, skipped_duplicates, first_date, last_date, opening_balance, closing_balance}`), derives `period_from/period_to`. Also warns (returns a flag, not an error) if the first new line's implied opening balance differs from the last imported closing balance. Atomic: all or nothing. `account_id` must be the `bank` money account.
3. **Matching, all owner-only SECURITY DEFINER functions:**
   - `suggest_bank_matches(p_statement_id) → table(line_id, candidate_kind, payment_id, entry_id, score, reason)`. Candidates are posted journal entries that touch the bank account with the same amount and direction and are **not already matched**: receipts/payments (`payments`, match by `instrument_no` = the line's `reference` first; cheques use `cleared_on`/value date), cash deposits (`cash_deposits`; amount + date window ±3 days, no reference), expense vouchers and other bank entries (amount + date). Order: reference token > amount + date window (±3 days, `value_date` for cheque deposits) with a **unique** candidate > narration token overlap as tie-break only.
   - `match_bank_line(p_line_id, p_entry_id, p_status)` (`'auto'` | `'manual'`): checks same bank account, correct direction (credit line ↔ entry debiting bank), **exact amount**, entry posted and not cancelled, entry not matched to any other line (unique partial index on `matched_entry_id`), line unmatched. Sets payment id when the entry belongs to a payment. `unmatch_bank_line(p_line_id)`; `ignore_bank_line(p_line_id, p_reason)` (e.g. own-account transfer noise; reason kept).
   - `auto_match_bank_statement(p_statement_id) → int`: applies only candidates with a **unique** reference match or a unique amount+date candidate as `'auto'`; anything ambiguous stays unmatched. Never creates entries.
4. **`v_bank_recon`** (admin-gated like `v_money_balances`): per statement/account — bank closing balance (last line), book balance of the bank account as at `period_to`, difference, unmatched statement lines (count, debit sum, credit sum), unreconciled book entries on the bank account dated ≤ `period_to` (count, sums), and `explained = difference == (book-only items − bank-only items)` so a non-zero unexplained figure is visible.
5. **Cancelled documents:** cancelling (reversing) a document whose entry is matched to a bank line must not silently leave a stale match. Either block with `DN_VALIDATION:bank_line_matched` until the line is unmatched, or auto-flag the line `unmatched`; pick the safer (block) and say so in the notes. Check `cancel_document`, `bounce_cheque` and `post_day_close` interplay.
6. **pgTAP** (empty DB): import good file; duplicate re-import imports 0 new; overlapping ranges import only the new tail; broken balance chain refused and rolls back; counter user and admin at aal1 can neither read nor call anything; amount mismatch / wrong direction / already-matched entry / cancelled entry all refused on `match_bank_line`; auto-match leaves ambiguous lines unmatched; same-day identical amounts match one-to-one; `v_bank_recon` difference explained after matching and after a book-only item; cancel of a matched document refused. Catalog guard 00026 must still pass (no anon-executable function, RLS on every table).

### Parser + app half (Sonnet)
7. **Pure parser `src/lib/bank-statement/hdfc.ts`** (+ vitest, fixtures in `src/lib/bank-statement/__fixtures__/` built from the research file's examples): input bytes/text/workbook → `ParsedLine[]` = `{ lineNo, txnDate (ISO), valueDate (ISO|null), narration, reference (string|null), debit (string), credit (string), balance (string|null) }`, money as **strings with two decimals, no floats** (strip grouping commas, parse via integer paise or string ops). Requirements from the research: find the header row by name set (`Date`+`Narration`+`Chq./Ref.No.` or the Delimited names `Value Dat`, `Debit Amount`, `Credit Amount`, `Chq/Ref Number`); skip the preamble, `****` rules and `STATEMENT SUMMARY` footer; accept `dd/mm/yy`, `dd/mm/yyyy`, ISO, Excel serials and Date cells (never `mm/dd`); blank/`0`/`0.00` = zero; strip BOM and a leading `'`; accept CRLF/LF; the Delimited unquoted-comma defence (date at the left, last numeric fields at the right, everything between is narration); keep the reference as a string, strip zero padding, null for all zeros; extract the RRN/UTR from the narration when the ref column is empty. **Formats: Delimited `.txt`/`.csv` and `.xlsx` (via `exceljs`). Legacy `.xls` cannot be read without the banned `xlsx` package: refuse it with the sentence "Save the statement as .xlsx, or download the Delimited (.txt) format".** Rows must come out oldest-first (reverse if the file is newest-first, detected by dates). Every refused file gives a plain sentence, never a stack trace. Also a **charge detector**: narration starting `FEE-`, `.`, containing `CHARGES`/`INCL GST` is tagged `kind: 'charge'` so the screen can offer "Book bank charge".
8. **Actions `src/app/actions/bank.ts`** (zod, `requireAdmin` which already means aal2, envelope, revalidate): `importBankStatement` (takes the **already parsed lines** the client previewed, not the file), `autoMatchStatement`, `matchBankLine`, `unmatchBankLine`, `ignoreBankLine`. **Create-from-line** does not need new posting code: from an unmatched **credit** line "Record receipt" opens the existing receipt flow prefilled (date = txn date, amount, mode = upi/neft/imps by narration, instrument_no = reference); from an unmatched **debit** line "Record payment / expense" opens the existing payment or expense-voucher flow prefilled (bank charges → the bank-charges expense account, full amount, **no GST split** unless the expense voucher already supports an input-GST line — log the default). After the entry posts, the action matches the line to it (`'manual'`). If the existing flows cannot be prefilled by a link, build a small modal that calls the same server actions.
9. **Screen `/reports/reconcile`** (owner only, admin at aal2; linked from Reports and the Cash & bank book): upload (drop zone) → **preview table before anything is saved** (first/last date, opening/closing balance read from the file, row count, any warning, a "this does not look like an HDFC statement" refusal) → Import. Then the statement view: tiles (bank balance, book balance, difference, unmatched lines), table of lines with status chip (matched / suggested / unmatched / ignored), per-line actions (Match…, Create entry, Ignore, Unmatch), "Auto-match" button, filter by status, 390 px layout (rows stack as cards). Statement list with each import's period and unmatched count. en + te strings. Matches the prototype's cash & bank book styling; no new tokens.
10. **Cheque clearing:** when a line is matched to a cheque receipt still `deposited`, offer one click "Mark cheque cleared" (calls the existing `markChequeCleared`); never automatic.

## Conservative defaults (log in implementation-notes.md)
1. Owner only (aal2 admin) for read and write, including the screen. Counter users never see it.
2. Auto-match applies only a unique reference match or a unique amount+date match; ambiguous = left for the owner.
3. The uploaded file is never stored; only parsed lines and the original file name.
4. Overlapping or repeated imports are safe (dedupe); a broken balance chain refuses the import.
5. Bank charges booked in full to the bank-charges expense account without GST split (ITC on bank charges is small; revisit with the owner).
6. A matched document cannot be cancelled until the line is unmatched.
7. Only the HDFC layouts in the research file; another bank = a new parser module, not a change here. Single bank account.
